# Caveman Skills Reference

Caveman mode reduces token usage and output length while keeping technical accuracy. When active, agents strip ceremony from their outputs: no preamble, no trailing offers, no restated context. Routing announcements fit in one line. Poirot findings are one line each. Colby reports what changed per file, not a prose session summary.

Ten skills make up the bundle: four workflow methodology skills that shape how Colby and Poirot work, two communication style skills that control output verbosity, two compressed agent variants selected by Eva automatically, and two utility skills available on demand.

---

## Activation and defaults

`caveman_mode: true` is the default in the `pipeline-config.json` generated by `/pipeline-setup`. New installs get it automatically. No extra step needed.

```json
{
  "caveman_mode": true
}
```

**Session override.** Type `/caveman` to toggle caveman mode on or off for the current session. This does not write to `pipeline-config.json`. The toggle resets when you close the IDE.

**Existing installs.** If your `pipeline-config.json` was generated before ADR-0062, the `caveman_mode` key is absent. An absent key is treated as `false` (backward-compatible). Re-run `/pipeline-setup` to add the key with the default `true` value, or add it manually to your config file.

## Communication style skills

### caveman

Base terse-communication mode. Eva applies it to routing announcements, phase transitions, and status updates when `caveman_mode: true`.

**Before (caveman off):**
```
Eva: I've reviewed the spec and the ADR. I'm going to route this to Colby for
implementation. This is a Medium-sized feature with two independent steps.
I considered starting with Poirot to write tests first, but given that we have
an existing test framework, I'll have Colby implement first. Let me know if
you'd prefer a different approach. Starting with Wave 1 now.
```

**After (caveman on):**
```
Eva: Colby — Wave 1. 2 independent steps. Alternative: Poirot tests first,
skipped — existing framework sufficient.
```

**Rules applied:** answer first, no preamble; fragments OK; 20-word max sentences; active voice; no hedging; no closers. Negations are never compressed away — "not done" stays "not done."

**Exceptions.** Caveman rules do not apply to security warnings, irreversible actions (deletion, force push, production deploys), or step-order sequences where partial omission causes incorrect execution. Those always use complete language.

### ultracave

Maximum compression. Grammar optional. One word when it carries enough meaning. Apply when caveman is still too verbose — deep investigation sessions, long pipelines, high message frequency.

```
Eva: Wave 1. Colby — Step 1.
Colby done. Gate running.
PASS. Step 2.
```

Same break-rules as caveman: security warnings, irreversible actions, and step-order sequences always use complete language.

## Workflow methodology skills

Eva loads these skills when invoking Colby or Poirot on specific task types. You do not invoke them directly.

### lean-build

**When Eva applies it:** Any build unit on a Medium or Large pipeline when `caveman_mode: true`.

Restricts Colby to the narrowest complete path. A candidate addition (config option, plugin point, extensibility hook, polish) must trace to an acceptance criterion or it is excluded. Colby delivers a coherent end-to-end path across responsible layers without adding surface area the spec does not require.

Stop condition: acceptance criteria pass. Not "the code looks complete."

### verify-and-stop

**When Eva applies it:** Poirot verification passes within a wave (focused checks before the full test gate).

Translates acceptance conditions into the smallest proof set. Runs focused checks first (targeted tests, grep, direct exercise). Falls back to the comprehensive test gate only if focused checks are insufficient. Stops the moment criteria pass. Outcomes reported as: `PASS`, `FAIL`, `UNAVAILABLE`, `BLOCKED`.

### surgical-patch

**When Eva applies it:** Colby fix units (after a Poirot finding) on any pipeline size when `caveman_mode: true`.

Fix only the layer directly responsible for the failure. No refactoring, no adjacent cleanup, no "while I'm here" changes. Stop when the failure resolves and regression tests pass.

### investigate-first

**When Eva applies it:** Colby units flagged as ambiguous (intermittent failures, performance problems) when `caveman_mode: true`.

Separates observed symptom from inferred cause before any code is written. No implementation until root cause is established with evidence (grep results, log lines, test output). Also documents why alternative hypotheses were ruled out.

Not for obvious typos or known bugs with a confirmed location.

## Cave agent variants

Cave agents are compressed-output versions of Colby and Poirot. Eva selects them automatically on Medium and Large pipelines when `caveman_mode: true`. You see the same routing announcements — the agents just produce shorter output.

### colby-cave

Scope: 1-2 files per invocation. Same engineering judgment as standard Colby. Output is compressed.

**Output format:**
```
path/to/file.ext:L{n}: [change in ≤5 words]. Verified: [how in ≤5 words].
```

**Example:**
```
source/shared/pipeline/pipeline-config.json:L27: caveman_mode field added. Verified: grep confirmed.
.claude/rules/agent-system.md:L14: routing table updated. Verified: read file.
```

**Too-big fallback.** If a task requires changes to more than 2 files, colby-cave returns: `too-big: [reason]. Use standard Colby.` Eva retries with standard Colby automatically. You see a note in Eva's next routing announcement: `Colby-cave: too-big. Retrying with standard Colby.` This is an automatic safety mechanism, not an error.

### poirot-cave

Same blind review discipline as standard Poirot — no spec, no ADR, no context. Output is compressed.

**Output format — one line per finding:**
```
path/to/file.ext:L{n}: {SEVERITY}: {problem}. {fix}.
```

Severity labels: `BLOCKER`, `FIX-REQUIRED`, `NIT`, `Q`.

**Before (standard Poirot):**
```
The PATCH endpoint in src/api/users.js around line 47 does not validate the
email format before saving to the database. This could allow malformed email
addresses to be stored. I recommend adding a format check before the database
write.
```

**After (poirot-cave):**
```
src/api/users.js:L47: FIX-REQUIRED: PATCH endpoint skips email validation. Add format check before DB write.
```

Zero findings: `0 findings. Exercised: [list]. Grep-verified: [list].`

> **Platform note.** Cave agent files (`colby-cave.md`, `poirot-cave.md`) are installed by `/pipeline-setup` to all three targets: `.claude/agents/` (Claude Code), `.cursor/agents/` (Cursor), and `.github/agents/` (VSCode Copilot). No platform-specific behavior differences.

## Utility skills

These skills are available on demand in any session, regardless of `caveman_mode`.

### caveman-review

Terse code review format. Each finding is one line. Use for PR reviews or when you want Poirot-style output outside a pipeline.

**Format:**
```
path/to/file.ext:L{n}: {emoji} {problem}. {fix}.
```

Severity: 🔴 bug, 🟡 risk, 🔵 nit, ❓ question.

Run `/caveman:review` or ask "review this diff in caveman format."

### caveman-commit

Terse commit messages for Ellis. Conventional Commits format, subject ≤50 chars. Body included only when the "why" is not obvious from the diff.

```
feat(pipeline-config): add caveman_mode field
fix(hooks): null-check AGENT_NAME before path enforcement
docs(user-guide): add cave agent variants section
```

### caveman-compress

Compresses a markdown file: strips filler phrases and redundant transitions while preserving every fact, decision, code block, and URL. Creates a `.original.md` backup before overwriting.

```
/caveman:compress docs/architecture/ADR-0010.md
```

**Example session:**
```
/caveman:compress docs/architecture/ADR-0010.md

Before: 623 words. After: 441 words. Reduction: 29%.
Backup: docs/architecture/ADR-0010.original.md
```

Files under 200 words: `too short — no gain` and stops.
Files 500+ words: targets ≥25% word reduction.

Heading structure, numbered lists, code blocks, file paths, and URLs are never touched.

### caveman-explore

Parallel citation-only code search. Issues multiple searches simultaneously and returns `path:START-END` citations only. No prose, no synthesis. Use it to locate relevant files fast before invoking another agent.

**Example:**
```
caveman-explore: src/validators/address.js:L1-L84  AddressValidator class definition
                 src/api/users.js:L47-L53  call site, email field
```

## Upgrading existing installs

If your install predates ADR-0062, the `caveman_mode` key is absent from your `pipeline-config.json`. The pipeline treats an absent key as `false`.

To enable caveman mode on an existing install, choose one:

**Option 1 — re-run setup (recommended).** Run `/pipeline-setup` again. Setup adds `caveman_mode: true` and installs the skill files to all three targets.

**Option 2 — manual.** Add the key to your config file:

```json
{
  "caveman_mode": true
}
```

Config file locations:
- Claude Code: `.claude/pipeline-config.json`
- Cursor: `.cursor/pipeline-config.json`
- VSCode: `.github/pipeline-config.json`

Manual config change enables cave agent selection and terse output but does not install the skill files. Utility skills (`/caveman:compress`, etc.) require the skill files from `/pipeline-setup`.

## Disabling caveman mode

**Config (persistent).** Set `caveman_mode: false` in your `pipeline-config.json`. Eva reads this at session start and disables cave agent selection, terse routing, and workflow methodology skill injection.

**Session (temporary).** Type `/caveman off` or "normal mode". Active for the current session only. Does not modify `pipeline-config.json`.

When `caveman_mode: false`:
- Eva uses standard Colby and Poirot (prose output)
- Routing announcements are verbose
- Workflow methodology skills are not injected into agent invocations
- Utility skills (`/caveman:compress`, `/caveman:review`, etc.) remain available
